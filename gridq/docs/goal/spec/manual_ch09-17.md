# Verification spec — manual chapters 09–17

Extracted from `docs/manual/chapters/09-dispatch.tex` … `17-cli.tex`. The SPEC is the tcolorbox
callouts (`rebuild`, `contract`, `caution`, `keyidea`) plus normative prose ("must", "never",
"always", "exactly", "identical"). Each row is a testable invariant. "Likely existing test" is the
closest match found by scanning `tests/` (`grep -n "def test_"`); "none found" means no test
plausibly asserts the invariant as stated. Source cites chapter + section/box.

Module map: M3 dispatch (ch09) · M4 sizing (ch10) · M6 scenarios (ch11) · M5/M9 finance+credit
(ch12) · X.2 quotes (ch13) · X.3 telemetry (ch14) · M8 outputs (ch15) · App (ch16) · CLI (ch17).

## Drift candidates (manual vs code/tests — record only)

1. **DST/timezone unspecified for the tariff calendar and dispatch series.** Ch09 keys prices "by period-start clock time" but never says which clock (UTC vs Europe/London) or what happens on the 46/50-half-hour clock-change days; the optimisation code has no timezone handling, and no test exercises a clock-change or leap-year (17,568-interval) series. Spec gap rather than a contradiction — but a rebuilt engine could legitimately differ.
2. **SoE behaviour across metered gaps is unspecified.** The manual mandates exclusion of missing half hours and the 8760/covered-hours annual factor, but is silent on chain-vs-segment. The code chains SoE across a gap as if the intervals were adjacent (`soe.roll(t=1)`, `src/gridq/optimisation/milp_solver.py:300,314`) — a battery "holds" across the gap and cannot act during it. No MILP test runs a gappy series.
3. **Value-by-stream sum-to-total has no exact test.** The manual demands an exact partition (arbitrage + DUoS = total priced bill reduction). `test_real_arbitrage_and_red_band_value_in_the_firm_floor` checks headroom==0 and positive floor streams but never asserts `sum(value_streams) == priced_revenue_gbp == objective value`.
4. **Ch09 describes exactly two solver implementations behind the dispatch seam** (real MILP + placeholder), and says the integer capability is "held in reserve" with live decisions continuous. The codebase also ships an MPC rolling-horizon solver that solves *binary* MILP windows (`src/gridq/optimisation/mpc_solver.py`, `milp_solver.py:181`, `tests/test_mpc_solver.py`) — undocumented in the manual.
5. **Ch12 states the annual charge volume "is a dispatch output that the current result schema does not yet carry."** Code already carries `annual_charge_kwh`/`annual_discharge_kwh` on the solver result and threads them via the engine hook (D13 promotion onto the frozen `OptimisationResult` is the open item per CLAUDE.md). The manual sentence will drift the moment D13 lands.
6. **Fade compounding untested.** The `(1−fade)^(year−1)` P50 revenue decay exists (`src/gridq/finance/cashflows.py:513`) and is normative in ch12 rebuild step 5, but no test pins the compounding (only the P90-below-P50 haircut is tested). The "honest degradation" claim rests partly on an unverified exponent.
7. **Sculpting basis recording untested.** `DebtTerms.sculpting_basis = "P90_DSCR"` exists (`src/gridq/finance/debt.py:37`) as the manual requires, but no test asserts the case records it.
8. **CLI `render` has no test.** Ch17 promises byte-for-byte re-render, `--site`-less "site context not supplied" sections, and warn-and-continue on a bad site file; `tests/test_cli_run.py` covers only `run`. The byte-identity guarantee is tested at the outputs layer, not through the `render` command.
9. **Warranty lookup edge behaviour untested.** The conservative floor lookup ("never reads off a higher-duration row") and the below-smallest-point warn-and-use-smallest rule (ch09 caution) have no tests; only the 4 h cap-binds case is covered.
10. **App overlay isolation and synthetic-profile invariants untested.** Ch16's walls — demo debt / upside overlays never touching a real-mode run or the record; synthetic profile summing exactly to the annual figure and grading only partial tier; reference-tariff fill never overwriting a supplied value; worst-observed-value chart floor "disclosed" — have no direct tests (only smoke-level coverage).
11. **Telemetry "no priced number leaks" untested.** Ch14's rebuild explicitly asks to test that no priced number ever enters an event; no such assertion exists.
