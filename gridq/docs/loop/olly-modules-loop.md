# Olly-modules hardening loop

Self-paced loop that drives **Olly's modules** to the `source_docs/System Requirements.html`
(System Brief) bar. State lives here; every iteration reads this file first and updates it.

- **Branch:** `loop/olly-modules` (work ONLY here; never `main`; never push).
- **In scope (Olly):** M0 `ingestion`, M1 `schemas`, M5 `finance`, M6 `scenarios`, M8 `outputs`,
  X.1 `assumptions`, X.2 `provenance`, X.3 `telemetry`.
- **Read-only (Olly):** M2 `value_stack`, M3/M4 `optimisation`/`engine`, M7 calibration. Do NOT edit;
  only read to keep the seam correct.

## Iteration cycle

1. Read this file. Pick the highest-priority `OPEN`, **code-ownable** item (Owner = `code`).
2. **Validate the item against the actual code first** — if it is already satisfied, mark it
   `GREEN (already met)` with evidence and move on; if stale/wrong, correct the row. (The backlog
   below is a v0 seed; ground every item before building.)
3. Implement the smallest correct change. Add or tighten the test that is its acceptance check.
4. **Quality bar — ALL must pass before the item is done** (run from repo root):
   - `/root/.venv/bin/ruff check .`
   - `/root/.venv/bin/ruff format --check .`
   - `/root/.venv/bin/mypy`
   - `/root/.venv/bin/pytest`
   - Invariant guards stay green: `test_app_templates_no_arithmetic`, `test_outputs_no_arithmetic_in_html`,
     `test_review_gates`, `test_optimisation_contract_conformance`, `test_quotes_telemetry`.
5. Update the item's row (Status + evidence). Append a one-line entry to the Progress log. Commit on
   the branch: `loop(<module>): <what changed>`.
6. Next iteration, next item.

## Guardrails (non-negotiable)

- **Never invent or hardcode a real assumption / financial number.** Numbers come from the
  assumption library or run inputs only. The deterministic core forbids it.
- **Never flip an output to `bankable` by fabricating inputs.** Bankability needs human-confirmed
  values (assumptions, debt terms, credit). Items needing those are `Owner = human`: build the
  *mechanism*, keep the honest `not_bankable`, and surface the blocker with its named owner.
- **Keep the invariants intact every iteration:** no LLM/arithmetic on the pricing path; the core
  never branches on `market == "GB"`; determinism (identical inputs+assumptions+seed → identical).
- **No silent scope-narrowing**; no "done" with a failing check. If blocked, log why and stop for Olly.

## Stop condition

Omit the next wake (stop the loop) when **every `code` item is `GREEN`**, a completeness critic
against the brief (for the scoped modules) finds nothing missing, and the only `OPEN` items left are
`Owner = human`. Post a final summary + the human-gated punch list.
