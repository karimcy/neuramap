## 1. What this goal is

Make the GridQ underwriting engine's numbers trustworthy enough to validate five real sites
(Grundon × 4 + Harwell), replacing an inappropriate 20% levered-IRR target with evidence-based
confidence bands, and produce a consulting-grade report from a resolved run.

The work ran as: **hostile review → literature survey → remediation → validation**.

caps the confidence band.

## 4. What changed in the pipeline (all with tests)

**New modules**
- `ingestion/hh_mandate.py` — validation Gate 2. No underwriting without a half-hourly basis;
  metered vs modelled recorded on the run and never inferred from the filesystem.
- `ingestion/hh_synthesis.py` — modelled load from a reference profile scaled to the site's own
  totals. With **monthly** totals the seasonal shape is MEASURED and only the within-month shape
  modelled.
- `ingestion/reconciliation.py` — Gate 3. Declared vs measured load, with warn/error thresholds.
- `value_stack/capacity_budget.py` — one asset, one power budget, plus the shared **energy
  sustainability** constraint (Xu et al.; Engels et al.; NESO product durations).
- `quotes/confidence.py` — low/medium/high bands. Every factor states a ceiling; the band is the
  **minimum**, so a strong input never compensates for a fatal one.
- `outputs/consulting_report.py` — the consulting report. Its "computes no number" invariant is
  enforced by an **AST test** that fails on any arithmetic operator in the module.

**Findings fixed:** F-01, F-02, F-03, F-07, F-10, F-11, F-15, F-16, F-17, F-19, F-26, F-52, H-1,
N3, N9, plus WP-1's labelling batch (N8, N15–N22, N30) and WP-2/WP-3. See each review's fix log for
the current authoritative list — **update it as you go**.

## 5. ⚠️ What a CLOUD session will NOT have

This is the most important section. **All site data is gitignored as sensitive customer intake**
(`.gitignore`: `data/`, `examples/real/`), and that policy is correct — do not override it.

A fresh clone therefore has **no**:
- source workbooks (`examples/real/Grundon/*.xlsx`, `examples/real/Harwell/*.XLSX`)
- the six site models (`examples/real/sites/*.json`)
- any half-hourly series (`data/sites/**`)

**Consequence: a cloud session can do all the code work but CANNOT run the site validations
(task 12).** To validate sites remotely you must supply that data to the environment out-of-band.

Everything is reproducible once the source workbooks are present:
```bash
python scripts/extract_site_data.py      # Harwell HH + Grundon monthly -> data/sites/
python scripts/generate_grundon_hh.py    # modelled HH series -> data/sites/hh/ + manifest
```
The six site models themselves are **not** regenerated by a script — they were hand-built and are
documented in `docs/grundon_harwell/04_site_models.md`.

## 7. The blocker on task 12

**Three of six sites cannot be sized at all.** Harwell, Colnbrook and Tanhouse have **no supplied
connection capacity**, so `mic_kw` was set to the observed or modelled peak as an explicit lower
bound. That leaves **zero charge headroom** — the battery cannot charge, so no candidate sizes.

This is an **external data dependency**, not a modelling problem: it needs the real MIC/ASC from
Grundon and Harwell. Bishops Cleeve (250 kVA), Knowl Hill (325) and Ewelme (750) have evidenced
capacity and can run.

Under `docs/validation_requirements.md` §3 this must surface as **"connection capacity unknown"**,
never as "no viable configuration" — a data gap must never be reported as an asset verdict.

## 8. Operating rules that bit repeatedly

- **The full test suite takes ~40 minutes.** `pytest -q` buffers all output when stdout is not a
  tty, so a killed run leaves an EMPTY log and tells you nothing. Run it in chunks that flush on
  exit — **never** pipe it through `tail`. macOS ships bash 3.2: no `mapfile`, no `${arr[-1]}`.
- **A fix is only as good as its narrowest call path.** Four fixes in this goal were correct in
  their module and wrong on the real path — a gate added at one call site while two others bypassed
  it, a schema rule never wired into the web intake. Check every call site.
- **An over-conservative constraint is still a wrong number.** Two fixes here erred in the opposite
  direction from the defect and had to be corrected.
- **Run the adversarial refutation pass.** It killed 7 of 38 findings with source-cited reasoning,
  including disproving a monotonicity claim. Findings without it are one-pass and unverified.
- Never invent a number on the pricing path. Refuse, or apply a sourced default that announces
  itself. Cite the constants-register row in a comment.
