## 1. Findings — Wave 6 (adaptive sizing search)

- **W6-1 · HIGH — warranty flooring is anti-conservative on the continuous domain, and the search exploits it.** `value_for_duration` floors; `warranty_cycle_limits.max_cycles_per_year_by_duration_h` DECREASES with duration (548/365/250 at 1/2/4 h). The MILP throughput cap (`branch milp_solver.py:308-316`) therefore RELAXES between keys: a 3 h candidate inherits the 2 h key's 365 cycles = 1095 kWh/kW-yr of monetisable throughput vs 730 (2 h point) / 1000 (4 h point). Off-key durations are the norm on `SizingDomain` (0.5–8 h continuous); the search preferentially selects just-below-key durations because they get the higher cap. Their D28's "conservative in the honest direction" reasons only from the increasing CM table. → C030 (proposed: conservative-neighbour lookup — floor on increasing tables, ceiling on decreasing — or step-quantised domains). Cross-ref goal FINDINGS F-002.
- **W6-2 · HIGH — no test pins the flooring direction on either lane.** `git grep value_for_duration …tests/` on the branch: nothing; all evaluator/deliverability tests use on-key durations (2.0 h) or stubs that never read the tables. D28 is recorded prose only.
- **W6-3 · MEDIUM — "step-aware by construction" holds only for the favourable-above-key direction.** `_step_line_points` (`branch search.py:192-215`) probes exactly ON d∈{1,2,4}; for a decreasing table the favourable plateau is at key−ε, never probed, and zoom rounds sample axis-aligned sub-grids that approach the diagonal e=k·p only geometrically — the refiner can land a full plateau-step below the dense grid's best just-below-key sample. Also: step probes are appended LAST and are the first points truncated under a tight budget (`search.py:246-253`); `step_durations` is hardcoded to `DEFAULT_DURATION_HOURS`, not derived from the actual table keys; no test exercises any piecewise-constant surface.
- **W6-4 · MEDIUM — certification is circular where it matters and the 0.5 % tolerance is not a test.** Adaptive is certified against the dense grid, but both share the evaluator — evaluator-level defects (W6-1) are invisible to the certification by construction; the dense reference's linspace grid lands on key lines only by accident. Tests assert 1 % (adaptive) / 5 % (PSO) on ONE smooth stub surface; the "within 0.5 %" and "several synthetic + real load shapes" claims in D29/issue-016 stage 8 are one-off dev-run records, asserted nowhere.
- **W6-5 · MEDIUM — end-of-tenor deliverability uses the NAMEPLATE duration's de-rating class at degraded energy.** `_assess_commitment` (`branch deliverability.py:106-124`) applies `derate(nameplate_duration) × (1−fade)^N`; as energy fades the duration at rated power shrinks (2.0 h → ~1.37 h at 15 y/2.5 %), which under the class convention drops the de-rating to the 1 h class — the code overstates degraded capability ~11 % at the key margins, i.e. a fabricated pass exactly where the check exists to police. Year-counting and honest-absence are correct.
- **W6-6 · MEDIUM — multiple commitments are assessed independently and AND-ed.** Two commitments each needing 0.6× of degraded capability both pass while jointly needing 1.2× (`deliverability.py:150-176`); no aggregation of concurrent committed kW. Same shape as W7-2 below.
- **W6-7 · MEDIUM — objective-metric uniformity is documented but never asserted.** `ScoredPoint`'s own docstring demands it; no search asserts it; selection rides `_METRIC_RANK` so a 0.01 % levered point outranks a 25 % project-IRR point in one mixed run; `SizingSearchResult` has no run-level metric; the benchmark labels a mixed run with its FIRST point's metric. D29's "records which metric it optimised" is per-point only.
- **W6-8 · LOW —** `pso_search` KeyErrors when `n_particles > max_evaluations` (`search.py:437-441`); the parallel harness compacts missing slots silently instead of failing loudly (`parallel.py:70-74`); PSO seeds two generators from the same seed (correlated streams); the LHS empty-result branch is dead code; duplicate budget warnings per truncated batch; step-probe rounding breaks for non-power-of-two future keys (`e/p` round-trip).
- **W6-9 · verified clean —** parallel-harness determinism is structurally sound (index-ordered reduction, per-worker evaluator, single-threaded seeded HiGGS solves, wall-clock confined to the labelled benchmark); parallel==sequential is pinned — though only with pure-Python stubs, so linopy/HiGHS thread-safety under the executor rests on one manual benchmark.

## 2. Findings — Wave 7 (firming substrate)

- **W7-1 · HIGH — committed kW can be undeliverable on the modelled floor and still pass + price.** The availability reservation `discharge − charge ≤ P − C_w` (`branch milp_solver.py:479-483`) reserves against rated power, but the model's own discharge bound is `min(power, load)` with no export variable — a commitment whose C_w exceeds in-window site load is "reserved" yet physically undeliverable as net injection; the only guard warns on C_w > rated power, never C_w > in-window load. Exactly the "assumed, not reserved" failure Wave 7 exists to kill.
- **W7-2 · HIGH — overlapping commitments double-sell the same kW.** Constraints are independent (binding = max(C1,C2), not the sum) while `deliverable_capacity_mw = Σ committed_power_kw` and valuation prices the sum: two 150 kW awards on a 200 kW battery each pass, dispatch reserves 150, pricing sells 300, no warning. Violates north_star §2's own "no double-sold kW".
- **W7-3 · HIGH — window/DUoS mapping repeats the F-003 tz bug class on a legal-obligation surface.** `_commitment_mask` uses raw `.month/.dayofweek/.time` and the branch calendar raw `.hour` — on a tz-aware (UTC-labelled) series a 17:00–19:00 local window sits at 18:00–20:00 BST all summer; no branch test uses tz-aware timestamps. (This lane's uncommitted `_hours_weekday` converts to Europe/London; the compiler must do the same — folded into the C026 response.)
- **W7-4 · HIGH — the CM "capability-checked" note asserts a check that can have failed.** `deliverable_capacity_mw` populates from compilation alone; in the branch's own undeliverable-commitment test the W7-3 verdict FAILS, the gate stays CONDITIONAL, yet `_capacity_market_value` prices the full committed kW with a note claiming it was capability-checked — a fabricated provenance claim on a £ figure. Same false note when no reference/check ever ran.
- **W7-5 · MEDIUM —** non-optimal solves DROP the compiled-constraint warnings (the over-commit/over-hold explanations and the HiGHS status) — the honest degrade loses exactly the evidence explaining why a contract made the LP infeasible; every non-optimal termination is labelled INFEASIBLE. Flex utilisation revenue prices ALL in-window discharge with no cap at committed kW (the model simultaneously treats the award as held-in-reserve and paid-as-delivered). Metered gaps inside committed windows are silently unconstrained (and the branch's global cyclic SoE chains across gaps — this lane's D31 segmentation fixes that side at merge). Constraint-name sanitisation can silently drop a second, different commitment on id collision. A window ending at midnight is unrepresentable (C026's "overnight = two windows" is impossible for the pre-midnight half). `produce_gate_context` lets one passing CM commitment set `deliverability_confirmed=True` while a sibling was unassessable; CONDITIONAL→CONTRACTED flips on any non-empty `reference` string with no record validation and no human-confirmation mechanism (north_star W2's "human confirmation is evidence" has no code counterpart).
- **W7-6 · verified clean —** C026's constraint algebra (signs, units, [start,end) mapping) matches the code; payload-less descriptors are byte-identical no-ops; frozen contracts genuinely untouched; the customer bill is validator-enforced arithmetic copied verbatim by the viewmodel; C029's interim peak figures carry the not-peak-optimised label; no wall-clock/RNG/`market=="GB"` in the new code.
