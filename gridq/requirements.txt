# GridQ — pinned runtime + [app] closure for the reproducible public deployment (W5-3).
#
# This is the EXACT, fully-pinned transitive closure the production web app needs, generated from
# the green test environment so the deployed image reproduces the tested behaviour bit-for-bit. It
# deliberately EXCLUDES the dev/agent toolchain (pytest, ruff, mypy, httpx, graphify, tree-sitter…)
# — those are not in the image.
#
# Why pinned: the solver stack (linopy / highspy / xarray, and their numeric deps numpy / scipy /
# pandas) is part of the deterministic-reproduction contract (docs/decisions.md D18 / D22). Exact
# pins keep the MILP byte-reproducible across rebuilds. The container additionally pins BLAS/OpenMP
# threads + TZ/locale (see Dockerfile) so determinism holds on any host CPU.
#
# The linopy "iceberg": linopy is pure-Python but `import linopy` eagerly imports linopy.remote,
# which top-level-imports requests + google-cloud-storage — so those (and polars / polars-runtime-32,
# dask, fsspec, numexpr, Bottleneck …) are REQUIRED for import, not optional. Do not prune them
# without re-checking `import linopy` in a clean env.
#
# Regenerate (when pyproject deps change): resolve the runtime+[app] closure and re-pin to the
# tested versions —
#   python -m venv /tmp/lockenv && /tmp/lockenv/bin/pip install --only-binary=:all: ".[app]"
#   /tmp/lockenv/bin/pip freeze --exclude-editable   # then reconcile against the test env
# (gridq itself is installed separately in the image via `pip install --no-deps .`.)
#
# Install (CI / image): pip install --only-binary=:all: -r requirements.txt
# `--only-binary=:all:` makes a missing wheel fail loudly instead of silently compiling from source.
