## Proposed text
- **User-facing docs (README / operating guide) must be verified against a real run, and must
  separate built from planned.** Before stating how the tool behaves, run it (`gridq run`,
  `gridq render`, `python -m gridq.app`) and document what actually happens — not what the code
  *looks* like it should do. Two traps this caught: a fresh `gridq run` produces a **`draft`,
  `not_bankable`** quote (not "indicative"), and the bundled example sites **degrade to
  `insufficient_data`** because their `half_hourly_file_ref` points at an uncommitted `data/` file
  (real meter data is gitignored) — the MILP reads the series from that ref, so a priced run needs a
  real `--hh` series. Label `indicative`/`gated`/`needs_review`/`not_bankable` honestly, and mark
  anything not yet built (e.g. the Wave-5 two-mode UI / visual flow / 3D surface) as planned, never
  as present fact.

## Evidence
W5-4 (README + operational docs rewrite, 2026-06-24 changelog entry). The pre-existing root
`README.md` claimed *"v1 scaffold stage… No application/pricing code exists yet"* while the entire
Wave-4 engine was built and green — a stale doc that would mislead any non-author. Writing the
replacement surfaced two behaviours that contradict the obvious reading of the code (draft-not-
indicative quote mode; examples degrading to insufficient_data without a committed series), both
found only by running the pipeline rather than reading it.

## Notes
