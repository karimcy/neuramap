One engine · one assumption set · three artifacts

GridQ — Sizing & Underwriting Engine

Given a behind-the-meter site, a single run produces three artifacts that are consistent by construction — the size, the price, and the financial case can never drift apart, because they are the same model viewed three ways.

Output 1
System specification

Power, energy and duration optimised for the site's own load, tariff, connection and locational value. AC-coupled, battery-only in v1.

Output 2
Underwriting pack

P50/P90 cashflows, DSCR sensitivities, contracted-vs-merchant split, counterparty credit — and the price that hits target return at the optimised dispatch.

Output 3
Customer proposal

Bill before and after, savings, term, structure — in plain language. The installer channel sells with this; the memo is for capital.

The pipeline

The consistency contract

1

One engine, called twice. Sizing searches specifications; underwriting prices the chosen one. Both consume the same dispatch engine, the same value stack, the same scenario set.

2

The bankable constraint sits inside the sizing objective. Maximise levered return subject to P90 DSCR ≥ covenant — the optimiser cannot select what underwriting would reject.

3

One versioned assumption library. No module holds private constants. A quote is valid only against the assumption version that produced it; material updates trigger repricing.

4

Deterministic. Identical inputs, assumption version and seed produce identical outputs. Every number traceable to its source.

Acceptance test 1 — bankable

Every output withstands an infrastructure fund's investment committee and a project-finance lender's credit desk. P50/P90 and DSCR are mandatory; point estimates are not deliverables.

Acceptance test 2 — fast

The system exists to compress quote cost. Telemetry measures time-to-quote and human-minutes against the manual benchmark — captured once, at the start, before the system erases it.

NEURA · SYSTEM BRIEFARCHITECTURE

Deterministic core, agentic perimeter

The pricing path contains no LLM and no stochastic AI — it is deterministic numerical code. A lender will not accept a language model pricing their asset. AI lives on the perimeter, where the human hours actually are: the back-and-forth over messy site data, counterparty research, document drafting. That boundary is what makes the output bankable, and the perimeter is where the cost compression lives.

The market interface

The most important design artifact in the system. Every value stream implements one interface, and the core consumes it generically:

  • Value function over a dispatch schedule
  • Constraints it imposes — availability windows, reserved power, held state-of-energy bands
  • Price & scenario inputs it consumes
  • Firmness & decay — penalty for non-delivery; price erosion over time
  • Availability gates — consents, metering, minimum aggregated portfolio capacity
  • Deliverability profile — capability the asset must hold in every contract year, checked at degraded capacity

The rule: if the core ever branches on market == "GB", the abstraction has failed. DUoS, CM, DC/DM/DR and Piclo never leak into the core modules.

NEURA · SYSTEM BRIEFMODULES

Module map

Thirteen modules; IDs are build references. CORE is deterministic and shared across markets. PERIMETER is agentic, schema-validated. CROSS-CUTTING binds every run.

M0  IngestionPERIMETER

Turns whatever an installer sends into a validated SiteModel. Grades every intake T0 (annual kWh + tariff + postcode), T1 (partial HH), T2 (≥12 months validated half-hourly). Returns a ranked list of the data that would most improve the quote — the back-and-forth becomes a precise ask. The biggest human-time sink in the business; the primary AI target.

M1  SiteModelCORE

The canonical schema: half-hourly load · connection (MIC/MEC, ASC band, voltage, ANM) · full tariff stack incl. levy lines · consents (G98/G99/G100, export MPAN, DNO application state) · supply boundary & supplier consent · physical pass/fail gates (footprint, fire separation) · counterparty. No archetype field exists — the engine reasons from the site's own data.

M2  Value & constraint stackCORE

Market mechanics as composable value functions and dispatch constraints — different price stacks, one MWh, one decision; double-counting structurally impossible. Gates enforced at quote time: a stream failing consents, metering or portfolio thresholds is priced out and listed as conditional upside with its unlock condition.

M3  Dispatch engineCORE

Half-hourly MILP on linopy/HiGHS. Physics include charge load counted against MIC/ASC, round-trip losses bought at the price actually faced, and parasitic load billed at the host tariff. Warranty cycle and throughput caps are hard constraints — overcycling is not available to the optimiser. Degradation: marginal-cost proxy in the objective, ex-post SoH model for life.

M4  Sizing optimiserCORE

Searches power, energy and duration against the bankable objective with P90 DSCR embedded. Day-one sizing for end-of-life capability — no augmentation, so the binding year may be late-life. Enumeration first; smarter search only if the solve-time benchmark demands it.

M5  Financial modelCORE

P50/P90 cashflows; debt sized and sculpted on the P90 case. Commercial structures are plug-ins — fixed £/kWh (default), savings share, capacity fee — with term, indexation and the buyout schedule explicit. Cost lines carried in full: levies on charge volume incl. losses, business rates, insurance, metering/IDNO, DNO costs. Installer capex sanity-checked against a benchmark library.

M6  Scenario engineCORE

Discrete, probability-weighted Low/Central/High price cases × policy branches. REMA's rejection of zonal pricing (Jul 2025) simplifies the locational axis. Time-to-energisation is a scenario axis — consenting timelines shift COD and the quote reports it. Monte Carlo deferred to portfolio work behind the same interface.

M7  CalibrationCORE

Backtests against historical GB data; the perfect-foresight haircut is calibrated, versioned and applied transparently — no confidence label is asserted without evidence. First validation set drawn from the cold-storage wedge as test-data selection, never a model input. Realised performance feeds back per stream.

M8  OutputsPERIMETER

Two documents from one run record: the underwriting memo (capital-facing — P50/P90, DSCR, firm-vs-conditional stream table, credit, consents and gate status) and the proposal (customer-facing — bill before/after, savings, term, structure, plain language). LLM drafts prose, human signs; every number from the run record.

M9  Counterparty creditPERIMETER

Creditsafe API plus a research agent produce an internal score and short credit memo. The score maps deterministically to discount rate and tenor policy in the financial model — no glowing return at a rate the covenant doesn't justify. Portfolio concentration flagged by counterparty, sector and region.

X.1–X.3  Assumption library · Provenance · Quote telemetryCROSS-CUTTING

One versioned source for every assumption — no private constants, diffable, reviewed on cadence. Every output number traceable to inputs + assumption version + code version. And every quote logged from day one: data tier at intake, human-minutes by person, installer iterations, win/loss with reason, realised-vs-underwritten after COD. Telemetry ships with the first quote, not after — retrofitted, it is worthless as evidence.

Why the floor does the work

Merchant front-of-meter revenue alone does not carry the £100k/MW/yr plan assumption. The behind-the-meter floor must — and the stack is built that way. Front-of-meter is labelled upside in every output until a partner's real numbers replace the placeholders.

A quote is a first-class object

Immutable record per state: inputs hash, data tier, assumption + code versions, outputs, history. The whole installer workflow hangs off two modes — fast and banded, or slow and firm.

Indicative — fast

Exists to make the installer channel quick. Banded outputs from minimal data, an expiry date, never cites gated streams — and ingestion returns the ranked list of data that would most tighten the number, so the follow-up is a precise ask.

Underwritten — firm

Full pack on validated half-hourly data; firm subject to listed conditions — consents, physical gates, credit. If the assumption library moves beyond tolerance before signature, the quote reprices. Nothing is reconstructed after the fact.

The telemetry dataset must answer, with numbers: time-to-quote vs the manual benchmark · marginal cost per quote · hit rate by data tier · underwriting error by stream. This is the falsifiable form of the cost-compression thesis — and a primary fundraising artifact. Measure the manual benchmark before the system makes it unmeasurable.

NEURA · SYSTEM BRIEFDECISIONS · BUILD ORDER · OPEN ITEMS

Resolved design decisions

  • AC coupling as default; coupling is not a search dimension.
  • No augmentation — the battery is sized once, day one, for end-of-life capability. Deliverability of every multi-year commitment is verified at degraded capacity.
  • Battery-only in v1; solar deferred to v2 with the net-load interface held open.
  • Scenario-based probabilistics — discrete weighted cases; Monte Carlo deferred to portfolio work behind the same interface. Honest coarseness beats false precision.
  • Bespoke MILP on linopy/HiGHS — a committed choice, not a preference. PyPSA survives only as an optional throwaway cross-check.
  • Front-of-meter on placeholder curves, labelled upside in every output, until the route-to-market partner conversation replaces them.

Non-functional floor

  • Bankable — P50/P90 and DSCR mandatory; point estimates are not deliverables.
  • Traceable — every number to inputs + assumption version + code version.
  • Reproducible — identical inputs, assumptions, seed → identical outputs.
  • Versioned — schema, assumptions, scenarios and code; every run records what it used.
  • Fast — indicative quote within a working hour of T0 intake; underwritten pack within five working days of raw T2 receipt. Placeholder targets — set before the first quote.
  • Confidential — half-hourly data held under recorded NDA state per site; access logged; sole-trader sites treated as personal data.

Build order & the one experiment

M0 + telemetry land with the first quote

Not after. The manual quoting benchmark is measured once, at the start — the first hand-built quotes are the control group for the entire cost-compression claim, and the system erases them.

The experiment that settles the rest

A single-site, full-year, half-hourly MILP solve-time benchmark on linopy/HiGHS. The result decides the outer-loop search method and whether temporal compression is ever needed. Nothing else is blocked on research.

Open questions

  • Route-to-market partner — the conversation that replaces every front-of-meter placeholder and decides which services get modelled precisely vs lumped as decayed upside.
  • Ancillary forecast source — a commercial provider for decay-curve calibration.
  • REMA tracking owner — a named person; scenario branches updated on policy events.
  • Supplier-consent precedent — how the battery's import interacts with the host's supply contract. The first real site sets the pattern.
  • Business-rates treatment of behind-the-meter BESS — confirm before it silently flatters every quote.
  • EMS / M&V interface owner — the underwriting dispatch envelope must export as the benchmark the operating system is measured against; an M&V method is required before savings-share contracts. Define the data contract in v1, build nothing else.
  • G99 / DNO execution owner — the system carries consent state; somebody has to drive it. Currently unowned.
